Прогноз спроса «товар × магазин × день» стоит на месте: прогоны 8, 9, 10, 12 дали
WAPE `score 1-3` в коридоре **0.4840–0.4850**. Семь изменений прогона 12 вместе дали

Переиспользовать её, а не писать новую агрегацию:

значит второй разрез не требует ни правки функции, ни склейки ключа в строку

Второй файл нужен для оси горизонта (Этап 4, ось D): рост WAPE по шагу *внутри ряда*.

**Подушевой Skill получается тем же дампом, даром.** `_model_rows` (строка 568) работает
с колонками `m_<имя модели>`, которые уже лежат в `in_score_segments` для каждой модели
из `evaluate.score_models` — а там есть `SeasonalNaive` и `Naive`. Значит рядом с
подушевым WAPE ансамбля пишется подушевой WAPE каждой оценённой модели:

```python
denom = in_score_segments.groupby(id_column, observed=True)['abs_target'].sum()
for name in score_models:
    column = f"m_{name}"
    if column not in in_score_segments.columns:
        continue
    error = (in_score_segments[column] - in_score_segments[target]).abs()
    by_series[f"wape_{name}"] = error.groupby(in_score_segments[id_column]).sum() / denom
```

Отсюда `Skill = 1 − wape_p50 / wape_SeasonalNaive` — операционный критерий отсечки
класса P0 (Этап 4.3) — считается без единого дополнительного прогона.

### A. Граница предсказуемости Πmax (§2.4.6.1, стр. 99–101) — считается даром

Формула книги:

```
Πmax = 1 − H_rate / log2(N)
```

`series_entropy.py` уже хранит `EntropyRate` **нормированным** на `log2(BINS)`, значит

```
Πmax_simple = 1 − EntropyRate          # ни одного нового вычисления
```

Упрощённая граница груба. Точная — через неравенство Фано (Song et al., как в книге,
стр. 101): решить относительно Π уравнение

```
H_rate = −Π·log2 Π − (1−Π)·log2(1−Π) + (1−Π)·log2(N−1)
```

бинарным поиском на Π ∈ [1/N, 1].

**Пример расчёта.** Ряд с N = 10 состояниями (BINS=10), H_rate = 1.2 бит/шаг:

* `Πmax_simple = 1 − 1.2 / log2(10) = 1 − 1.2/3.3219 = 0.639`
* Фано, подбор Π:
  * Π=0.80 → H(0.80)=0.7219; 0.20·log2 9 = 0.20·3.1699 = 0.6340; сумма 1.356 > 1.2
  * Π=0.85 → H(0.85)=0.6098; 0.15·3.1699 = 0.4755; сумма 1.085 < 1.2
  * Π=0.83 → H(0.83)=0.6577; 0.17·3.1699 = 0.5389; сумма **1.197 ≈ 1.2** → `Πmax_fano ≈ 0.830`

Разница 0.64 против 0.83 велика, писать обе колонки.

> Πmax — вероятность угадать **бин**, а не точность в штуках. Мост к WAPE строить не
> теоретически, а эмпирически: регрессия подушевого WAPE на Πmax (Этап 3).

### B. Выборочная энтропия SampEn (§2.4.7)

```
SampEn(m, r) = −ln( A^m / B^m )

B^m = #{ (i,j), i≠j : d_Chebyshev[ X_m(i), X_m(j) ] ≤ r }
A^m = то же для длины m+1
```

Параметры книги: `m = 2`, `r = 0.2·σ`. Реализация — `numba @njit`, иначе O(n²) на
236 тыс. рядов нереален.

**Пример расчёта.** x = [0,0,3,0,0,4,0,0,3,0], n=10. σ = 1.549, r = 0.2·1.549 = **0.310**.

Векторы длины 2 (i = 1…8):
`(0,0) (0,3) (3,0) (0,0) (0,4) (4,0) (0,0) (0,3)`
Совпадения в пределах r: `(0,0)` встречается 3 раза → C(3,2) = 3 пары; `(0,3)` дважды → 1 пара.
`(0,3)` и `(0,4)` не совпадают: max(0, 1) = 1 > r. → **B = 4**

Векторы длины 3:
`(0,0,3) (0,3,0) (3,0,0) (0,0,4) (0,4,0) (4,0,0) (0,0,3) (0,3,0)`
→ `(0,0,3)` дважды, `(0,3,0)` дважды → **A = 2**

`SampEn = −ln(2/4) = ln 2 = 0.693`

> **Ловушка нулей.** При 62% нулей и малой σ все нулевые окна совпадают, B и A разом
> велики, SampEn → 0, и ряд ложно выглядит «супер-регулярным». Поэтому: (1) r считать
> от σ **ненулевых** значений, колонка `SampEnNz`; (2) обязательно прогнать через
> суррогаты (Этап 2). Артефакт того же рода уже дважды ловили — `Acf7` и `TopDayShare`.

### C. Многомасштабная энтропия MSE (§2.4.9)

Укрупнение непересекающимися окнами:

```
y^(τ)_j = (1/τ) · Σ_{i=(j−1)τ+1}^{jτ} x_i ,   j = 1 … ⌊N/τ⌋
E(τ)    = SampEn( y^(τ) ; m, r )        r фиксируется по σ ИСХОДНОГО ряда
```

τ ∈ {1, 2, 3, 7}. При N = 365 и τ = 7 остаётся 52 точки — предел применимости
(книга: «эффективная длина ~ N/τ»); τ = 14 (26 точек) считать, но помечать
`MseTau14Reliable = 0`.

**Почему это важно именно нам.** τ = 7 — недельное укрупнение: оно *снимает* недельный
ритм, который модель уже эксплуатирует (WAPE ансамбля / SeasonalNaive = 0.73–0.77 по
всем классам ритма). E(7) отвечает на вопрос «а что осталось *сверх* дня недели» —
то есть ровно на вопрос, упёршийся в 0.484.

Сводки кривой: `MseAuc = Σ_τ E(τ)`, `MseSlope = E(7) − E(1)`.
Читается по книге: плоская кривая на высоком уровне = шум; рост по τ = настоящая
многомасштабная структура.

### D. SVD-энтропия (§2.4.11)

```
X = матрица траектории (вложение m = 10, задержка τ = 1)
X = U Σ Vᵀ,  σ_1 … σ_r
σ̄_i = σ_i / Σ σ_j
H_svd = −Σ σ̄_i log2 σ̄_i ,  нормировка на log2(m)
```

Дёшево: SVD матрицы 356×10, минуты на всю выборку.

**Контрольный пример (сверка реализации).** Для чистой синусоиды матрица траектории
имеет ранг 2 → σ̄ ≈ (0.5, 0.5, 0, …) → H = 1 бит → 1/log2(10) = **0.301**.
Книга (рис. 2.11) даёт ровно 0.301 для периодического ряда и 0.995 для случайного.
Расхождение с этими числами = ошибка в коде.

### E. Плоскость сложность–энтропия CECP (§2.4.13) — главная недостающая ось

Перестановочная энтропия у нас есть, но **одна она не отличает белый шум от
структурированного-но-нелинейного** — прямая формулировка книги (стр. 141). Вторая
координата — статистическая сложность Ламберти:

```
P     = распределение ординальных паттернов (Bandt–Pompe, m)
P_e   = равномерное распределение по m! состояниям
H_s   = S[P] / log(m!)                            нормированная энтропия
D_JS  = S[(P+P_e)/2] − S[P]/2 − S[P_e]/2          дивергенция Йенсена–Шеннона
C_JS  = Q_0 · D_JS(P, P_e) · H_s[P]

Q_0 = −2 · { ((M+1)/M)·ln(M+1) − 2·ln(2M) + ln(M) }⁻¹ ,   M = m!
```

**Пример расчёта Q_0 для m = 3** (M = 6):

```
(7/6)·ln 7  = 1.16667 · 1.94591 = 2.27023
2·ln 12     = 2 · 2.48491       = 4.96981
ln 6                            = 1.79176
сумма = 2.27023 − 4.96981 + 1.79176 = −0.90782
Q_0 = −2 / (−0.90782) = 2.2031
```

Для m = 4 (M = 24) тем же путём `Q_0 = 1.6510`.

Считать при m = 3 (сопоставимо с текущей `PermutationEntropy`) **и** m = 4
(24 паттерна, 362 окна — статистики хватает, разрешение выше).

Интерпретация по книге:

| (H, C) | Что это | Решение |
|---|---|---|
| H ≈ 1, C ≈ 0 | белый шум | не моделировать |
| H ≈ 0, C ≈ 0 | тривиальная периодика | простейшая модель |
| H средняя, C **высокая** | структурированный нелинейный | кандидат на сложную модель |

### F. Тест отношения дисперсий VR(k) (§2.4.5, Lo–MacKinlay)

```
VR(k) = Var(y_t − y_{t−k}) / ( k · Var(y_t − y_{t−1}) )

z = (VR(k) − 1) / √( 2(2k−1)(k−1) / (3kN) )   ~ N(0,1)
```

Считать k ∈ {2, 7, 14}. Ключевой — **k = 7**: это наш горизонт.

**Пример расчёта порога значимости.** N = 365, k = 7:

```
знаменатель = √( 2·13·6 / (3·7·365) ) = √(156 / 7665) = √0.020352 = 0.1427
|VR(7) − 1| > 1.96 · 0.1427 = 0.280   ⇒ значимо на 5%
```

Интерпретация книги: VR < 1 — возврат к среднему (недельная агрегация «успокаивает»
ряд ⇒ недельный заказ предсказуем лучше суточного); VR ≈ 1 — случайное блуждание;
VR > 1 — тренд/персистентность.

### G. Экспонента Хёрста (§2.5.6, п. 12) — через DFA

R/S на 365 точках шумит; брать DFA (detrended fluctuation analysis):

```
1) Y(k) = Σ_{i≤k} (x_i − x̄)                     интегрирование
2) разбить Y на окна длины s, в каждом снять линейный тренд МНК
3) F(s) = √( среднее квадратов остатков )
4) F(s) ~ s^H  ⇒  H = наклон регрессии log F(s) на log s
```

s ∈ {7, 14, 28, 56, 91}. Градации книги: H = 0.5 шум/случайное блуждание;
H > 0.5 персистентность (тренд); H < 0.5 возврат к среднему.

### H. Экспонента Ляпунова и горизонт τ_f (§2.4.17)

```
d(t) ≈ d(0) · e^(λmax · t)     ⇒     τ_f ≈ 1 / λmax   (в шагах = днях)
```

Метод Розенштейна (устойчив на коротких зашумлённых рядах): вложение по Такенсу
(m из ложных ближайших соседей, τ из первого минимума взаимной информации), для каждой
точки ближайший сосед с исключением Тейлера, `⟨ln d_j(i)⟩` по j, λmax = наклон линейного
участка.

**Зачем.** Замерено: WAPE по шагам почти плоская — 0.4768 / 0.4867 / 0.4905 / 0.4894 /
0.4966 / 0.4942 / 0.4951, за 7 дней всего +0.018. Журнал трактует это как «прогноз мало
опирается на свежую историю». λmax проверяет трактовку: если у большинства рядов
τ_f ≈ 1–2 дня, плоскость означает, что модель уже на шаге 1 работает уровнем, а не
памятью; если τ_f велик — горизонт можно расширять, и потери там, где мы не смотрим.

> Ограничение: на рядах с ZeroShare > 0.3 Розенштейн даёт мусор. Считать на плотных
> рядах и на недельно-укрупнённом ряде; вне области применимости писать NaN,
> а не число.

### I. Тест Кабудана на перемешивание (§2.4.2, стр. 94)

Единственная мера главы, прямо привязанная к ошибке: «если у ряда есть осмысленная
временна́я структура, модель должна работать на исходных данных лучше, чем на тех же
значениях в случайном порядке».

Модельно-независимый дешёвый вариант:

```
η = 1 − WAPE_SeasonalNaive( x ) / median_b WAPE_SeasonalNaive( shuffle_b(x) )
```

B = 20 перестановок. Перемешивание разрушает всю временную структуру, сохраняя
распределение — значит η изолирует ровно «сколько структуры эксплуатируемо лаговой
моделью». Считается за микросекунды.

**Пример расчёта.** Ряд «продаётся только по субботам»: `[0,0,0,0,0,10,0] × 52`.
SeasonalNaive с лагом 7 воспроизводит его точно → WAPE = 0. Перемешанный ряд теряет
привязку к дню → WAPE ≈ 1.7. `η = 1 − 0/1.7 = 1.0` — структура полностью
эксплуатируема. Для пуассоновского шума WAPE обоих рядов одинаков → η ≈ 0.

Считать также `η_naive` (лаг 1) — разность `η_SN − η_naive` отделяет календарь от
инерции, то есть ту же пару осей, что уже разделили `WeekdayShare` и `Acf1`.

### L. Спектральная концентрация вместо EMD/VMD (§2.4.15–2.4.16)

Правило книги: «ряды, у которых ≥ 60% энергии сосредоточено в 1–2 модах, вероятнее
всего прогнозируемы». `PyEMD` / `vmdpy` нет ни в одном окружении, а разложение стоит
дорого. Дешёвый эквивалент по той же периодограмме, что уже считает `_spectral_entropy`:

```
PowerTop2   = ( S(f_(1)) + S(f_(2)) ) / Σ S(f)          доля двух сильнейших бинов
PowerWeekly = ( S(1/7) + S(2/7) + S(3/7) ) / Σ S(f)     доля недельных гармоник
```

Порог 0.60 переносится напрямую.

### Стоимость

| Класс | Меры | Объём |
|---|---|---|
| O(n) / O(n log n) | Πmax, CECP, VR, PACF, PowerTop2/Weekly, η Кабудана, Хёрст | **все 236 108 рядов** |
| O(n²), numba | SampEn, MSE(τ) | стратифицированная подвыборка **30 000** рядов (пропорционально ячейкам `Quadrant × RhythmClass`, не менее 500 на ячейку) |
| хрупкие | λmax Розенштейна | только ZeroShare < 0.3 плюс недельное укрупнение |

Выход: `preprocessing/data/dimension/predictability.parquet`.

## Этап 2. Калибровка на суррогатах — что мера меряет при 62% нулей

Пропустить этот этап нельзя. Проект уже дважды получил меру, которая измеряла не то,
что предполагалось: `Acf7` мерила инерцию уровня, а не ритм (корреляция с `Acf1` 0.584
против 0.255 с `WeekdayShare`; 71.7% «ритмичных» рядов ритма не имели); `TopDayShare`
мерила разреженность, а не выбросы (100% «выбросов» — в lumpy + intermittent).
Все меры главы 2 разработаны для плотных стационарных сигналов, у нас 61.9% нулей.

Сгенерировать 8 семейств рядов длиной 365 с **известным ответом**:

1. пуассоновский белый шум;
2. чистая недельная сезонность;
3. недельная сезонность + шум (SNR 1:1);
4. линейный тренд + шум;
5. AR(1), φ = 0.7;
6. случайное блуждание;
7. прерывистый пуассоновский (Кростон-подобный);
8. базовый уровень + редкие всплески ×3 (имитация промо).

Каждое — при ZeroShare ∈ {0, 0.3, 0.6, 0.8, 0.9}, прореживание двумя способами:
случайной маской и **блочной** маской (имитация out-of-stock — именно она у нас и есть).
По 200 реализаций.

Результат — таблица «мера × семейство × ZeroShare × тип маски». **Критерий отбора:**
мера остаётся в наборе, только если при ZeroShare = 0.8 она всё ещё разделяет семейство
(2) и семейство (1) с эффектом ≥ 1 стандартное отклонение. Иначе — либо ограничение
по применимости, либо исключение.

Побочный, но обязательный результат: контрольные значения книги должны воспроизвестись
(см. «Проверка»).

## Этап 3. Валидация: коррелирует ли предсказуемость с реальной ошибкой

Воспроизведение Catt / Scholz-Reiter на наших данных. Вход: `series_metrics.parquet`
(Этап 0) + `series_entropy.parquet` + `predictability.parquet`.

1. **Ранговая корреляция** Спирмена каждой меры с подушевым `wape_p50`,
   **взвешенная по `target_sum`**. Взвешивание принципиально: 50.9% строк —
   intermittent, но лишь 23.7% объёма; невзвешенная корреляция опишет мусор.
2. **Децильные таблицы**: WAPE, BIAS, `target_sum`, число рядов по децилям каждой меры.
   Ячейка с долей объёма < 2–3% — шум, сливать с соседней (правило из
   `docs/series_classification.md` §6).
3. **Разделение внутри ячейки.** Мера полезна, только если разделяет WAPE
   **внутри** `Quadrant × RhythmClass`. Иначе она переоткрывает разреженность —
   как `TopDayShare`. Планка сравнения: существующий размах `Quadrant` 0.348–0.714,
   `RhythmClass` 0.351–0.523; самое сильное существующее разделение —
   `intermittent | strong` 0.496 против `intermittent | none` 0.679.
4. **Отбор некоррелированных.** Матрица корреляций между самими мерами; из групп с
   |r| > 0.6 оставить по одному представителю (предпочитая дешёвый и устойчивый
   на суррогатах).
5. **Проверка Πmax как потолка.** Регрессия подушевого WAPE на Πmax; проверка,
   что фактическая ошибка *ниже* границы нигде не оказывается систематически —
   если оказывается, дискретизация (BINS = 10, квантили ненулевых) выбрана неверно.
6. **Разность `_raw` vs `_dem`.** Сколько «непредсказуемости» снимается вырезанием
   дней отсутствия товара. Прямо объясняет, почему `target_with_nulls` сдвинул
   Croston на −0.181, а Chronos2 на −0.034.

## Этап 4. Классификация

Строится **из измерений Этапа 3**, а не из теории. Метод фиксируется здесь, конкретные
пороги — после замера. Порядок ровно тот, которым калиброван `RhythmClass`: теоретическая
граница → перцентили → проверка по WAPE.

### Ось A — режим спроса (без изменений)

`Quadrant` по ADI-CV, пороги 1.32 / 0.49. Измерено, работает: 0.348 / 0.487 / 0.668 / 0.714.

### Ось B — календарная структура (без изменений)

`RhythmClass` по `WeekdayShare`, пороги 0.034 / 0.06 / 0.12. Измерено: 0.351 / 0.398 /
0.463 / 0.523. **При смене длины истории порог пересчитывать** (182 дня → 0.069).

### Ось C — используемая предсказуемость (новая)

Метод построения:

1. Из мер, прошедших Этапы 2 и 3, взять 2–3 некоррелированные.
2. `PredictabilityIndex` — их взвешенная сумма; веса из изотонической регрессии
   подушевого WAPE на меры внутри ячейки `Quadrant × RhythmClass`.
3. Границы классов — по излому кривой WAPE(индекс), с проверкой, что каждая ячейка
   держит ≥ 3% объёма.

**Предварительные градации** (гипотеза до калибровки; названия — по решению, а не по
величине):

| Класс | Правило (провизорное) | Смысл | Решение |
|---|---|---|---|
| **P0 «шум»** | Ω < 0.10 **и** C_JS < 0.05 **и** η_SN < 0.05 **и** Skill ≤ 0 | структуры нет | не моделировать |
| **P1 «уровень»** | η_SN > 0.05, но PowerWeekly < 0.10 и EffectiveArOrder ≤ 1 | предсказуем уровнем | дешёвая модель |
| **P2 «календарь»** | PowerWeekly ≥ 0.10 **или** WeekdayShare ≥ 0.034 | лаговая/сезонная работает | текущий ансамбль |
| **P3 «сложный сигнал»** | C_JS в верхнем дециле при H_s ∈ [0.4, 0.8] | нелинейная структура | отдельное моделирование |

Ожидаемая проверка на согласованность: 52.8% рядов сейчас имеют инерцию без ритма,
25.5% — ни того ни другого. P1 должен примерно совпасть с первой группой, P0 — со
второй; сильное расхождение означает, что новая ось действительно несёт что-то сверх
`Acf1`/`WeekdayShare`, и это надо разбирать, а не замалчивать.

**Операционный порог отсечки P0 — не «красивое число», а Skill ≤ 0**: ансамбль на этих
рядах не лучше `SeasonalNaive`. Величина измеряется, а не назначается.

### Ось D — горизонт

`HorizonClass` по τ_f = 1/λmax, градации {≤1, 2–3, 4–7, >7 дней}. Кросс-проверка:
внутри класса должен воспроизводиться фактический рост WAPE по шагу из
`series_metrics_by_step.parquet`. Если не воспроизводится — λmax на наших данных
не работает, и это тоже результат (фиксировать, а не прятать).

## Этап 5. Применение — четыре решения

### 5а. Квантиль выгрузки по классу

`predict.quantile_by` реализован, но **ни разу не прогонялся** (блок в конфиге
закомментирован). Уровни по `Quadrant` посчитаны: 0.524 / 0.532 / 0.581 / 0.582
(прогон 12). Пересчитать те же уровни по новому классу предсказуемости и сравнить
цену де-смещения. Ключ разреза меняется с `Quadrant` на класс — сама механика готова.

### 5б. Отсечка «не прогнозируем»

Сегодня отсечка стоит по `min_nonzero_days` — то есть по **разреженности**.
Заменить критерием предсказуемости (класс P0 / Skill ≤ 0) и замерить: какая доля объёма
уходит, как меняется WAPE на оставшемся, что происходит с BIAS. Это прямая рекомендация
книги §2.5.2: «паттерны с высокой энтропией предполагают альтернативные стратегии,
такие как увеличение резервных запасов».

### 5в. Разрезы метрики и объяснение потолка

Добавить в `evaluate.score_segments`: `PredictabilityClass`, `Quadrant|PredictabilityClass`,
`HorizonClass`, децили `Forecastability`. **Ни одного переобучения не требуется.**
Итог — разложение 0.4846 по классам с указанием, где потолок достигнут, а где нет.

### 5г. Признаки в модель / маршрутизация — последним и с критерием остановки

Замерено, что ось регулярности как признак не работает: `Cv2` −0.0001, `Quadrant` 0.0004,
`ZeroShare` 0.0072 — доверительные интервалы через ноль. Маршрутизация по `Quadrant`
отвергнута: ансамбль выигрывает в каждом классе спроса. Книга тоже относит эти меры к
диагностике, а не к признакам.

Поэтому — только после 5а–5в, и с заранее объявленным критерием: подать в static features
**одну** лучшую меру оси C и одну ось D; принять, только если `p99_low > 0` в
`feature_importance.csv` **и** `score 1-3` улучшился более чем на 0.003 (разброс между
окнами 0.03–0.06, так что меньшее движение неотличимо от шума). Иначе — зафиксировать
отрицательный результат в журнале и закрыть направление.

Отдельно — **сегментное смешивание на промо-днях**: `DirectTabular` единственная модель,
у которой на акциях смещение *меньше* (−0.0089 против −0.0348 в обычные дни), а вес в
ансамбле всего 0.14. Это независимое от предсказуемости направление, но оно тоже открыто.

`1 − EntropyRate` прямо из `series_entropy.parquet`; новая перестановочная энтропия

**3. Сходимость подушевого дампа с агрегатом.**
`Σ_i abs_err_p50_i / Σ_i abs_target_i` по `series_metrics.parquet` должна точно
совпасть со строкой `score` / `1-3` в `holdout_metrics.csv` (**0.484620** для прогона 12),
а `Σ target_sum` — с 3 355 723.669 и `Σ rows` — с 1 051 775. Расхождение означает,
что дамп берётся не из того подмножества.

**4. Полезность оси.** Разброс WAPE по классам новой оси **внутри** ячейки
`Quadrant × RhythmClass` сравнивается с существующим лучшим разделением (0.496 против
0.679). Меньше — ось не добавляет ничего.

**5. Сопоставимость.** `num_windows`, `window_step`, `score_horizon`, `score_filter`,
состав рядов не менять. Проверка: совпали `rows` и ключи `window`.
